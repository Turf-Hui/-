## 2. 获取方式合规性说明（白名单、非爬虫）

课程规定数据获取须通过以下白名单方式之一：① 数据源官方一次性下载文件（CSV/ZIP/XLSX/JSON）；② 官方或社区维护的 Python 数据接口库（`tushare`/`akshare`/`yfinance`/`pandas-datareader`/Kaggle 官方 CLI 等）；③ 政府/国际组织开放平台公开数据文件下载。

本项目采用**方式 ①**：由 `scripts/01_load.py` 对 UCI 官方静态文件地址 `https://archive.ics.uci.edu/static/public/352/online+retail.zip` 发起一次性文件下载。该 ZIP 为 store（未压缩）模式，脚本直接从字节流中剥离外层 ZIP 本地头，把内部官方 `Online Retail.xlsx` 原文件（23,715,344 字节）落盘为 `data/raw/OnlineRetail.xlsx`；由于该服务器忽略 Range 请求且慢速网络下连接易中断，脚本实现了「断线重连后跳过已下载字节、追加写入」的续传机制。整个获取过程：

- **未使用** Scrapy、Selenium、`requests + 网页解析`、模拟登录、HTML 解析等任何爬虫技术；
- **未**遍历网站页面、**未**批量构造 URL、**未**绕过任何访问控制；
- 仅对课程附件 A 白名单内数据源的**一个官方文件地址**发起一次文件下载请求；
- 原始数据文件留存于 `data/raw/`，可供复核与重复运行。

`scripts/01_load.py` 中 `_ensure_source_file()` / `_download_uci_stream()` 会在本地文件缺失或完整性校验不通过时自动从上述官方 URL 续传补下载，保证仓库克隆后一键复现；所下载的是 UCI 官方发布的原始 XLSX 字节，未对数据内容作任何修改。

## 3. 抽样方法与随机种子（课程 2.1 第 3 条）

原始 54 万行若全量参与 Apriori 与可视化计算开销过大，故进行抽样：

- **抽样单元**：以「发票 `InvoiceNo`」为抽样单元，而非逐行抽样。原因在于购物篮/关联规则分析依赖同一发票内的商品共现结构，逐行抽样式会破坏订单完整性。
- **抽样方法**：等概率、无放回简单随机抽样，保留被抽中发票的**全部明细行**。
- **随机种子**：`RANDOM_SEED = 42`，使用 `numpy.random.RandomState(42)`，结果完全可复现。
- **抽样规模**：基础治理后有效记录 391,150 行、18,402 张有效发票；保留 `SAMPLE_INVOICES = 1500` 张发票的**全部明细行**，得到 33,496 行，清洗去重 373 行后最终事实表 **33,123 行**（客户 1,049 · 商品 2,919 · 补充评论 18,357），实际数值见 `data/raw/data_overview.json` 与 `data/clean/clean_report.json`。
- **合规性**：抽样后主表记录数仍**远超"不少于 500 条"**的要求。

## 4. 补充生成数据（课程 2.1 第 3 条要求"单独标注"）

UCI Online Retail 原始数据集**不含**客户画像、商品类目、成本、渠道、评论文本等字段。为支撑 RFM、帕累托/ABC、波士顿矩阵、情感分析等模型，依据课程"若所选数据源规模不足，可用 Faker 按给定 Schema 补充生成维度表或明细表（补充部分须单独标注）"，对以下字段作**补充生成并单独标注**：

| 补充字段 | 所在表 | 生成方式 | 标注 |
|---|---|---|---|
| `gender` / `age` / `member_level` | dim_customers | Faker 按 Schema 生成 | 【补充-Faker】 |
| `name` | dim_customers | Faker 生成（分析不使用） | 【补充-Faker】 |
| `category` / `sub_category` | dim_products | 由**真实** `Description` 关键词规则派生 | 【补充-规则派生】 |
| `brand` | dim_products | Faker 生成 | 【补充-Faker】 |
| `price` | dim_products | 取该商品**真实** `UnitPrice` 中位数 | 真实派生 |
| `cost` | dim_products | 按 40% 毛利率估算（0.6 × price） | 【补充-估算】 |
| `channel` / `payment` | fact_orders | Faker 生成 | 【补充-Faker】 |
| **整张 `fact_reviews` 评论明细** | fact_reviews | Faker 生成中文评论与评分 | 【补充-Faker】仅用于情感分析模型 |

标注位置：① `scripts/01_load.py` 字段级行内注释；② `data/raw/data_overview.json` 的 `real_fields` / `supplement_fields` / `supplement_note` 键；③ 本声明本表；④ `README.md` 数据来源表；⑤ 论文第 2.1 / 2.4 节。

**核心交易度量（发票号、商品码、客户号、日期、数量、单价、金额、国家）全部来自 UCI 真实数据，未做任何合成或篡改。** 补充字段仅用于补充维度与文本模型，且不参与 GMV、RFM 的 R/F/M、销售趋势、国家分布等真实结论的计算。

## 5. 基础治理与导出（课程 2.1 第 4、5 条）

`scripts/02_clean.py` 完成：

1. **缺失值处理**：`CustomerID`、`InvoiceDate`、`Quantity`、`UnitPrice` 关键字段缺失记录剔除；
2. **异常值识别**：剔除取消单（C 开头）、负数量、非正单价、非商品费用码（POST/DOT/M 等），并用 IQR 法标记金额异常单独输出 `amount_outliers.csv`；
3. **重复值去除**：按全字段去重，并按「订单-商品-客户-日期」复合键去重；
4. **类型与日期格式统一**：金额/数量数值化，`InvoiceDate` 解析为 datetime，派生 `order_month` / `year` / `month`；
5. **多表主外键对齐**：剔除事实表中不存在于维度表的客户/商品引用，构建星型模型（fact_orders + dim_customers + dim_products + fact_reviews）。

实测结果（`data/clean/clean_report.json`）：关键字段缺失 0 条、重复 373 条（已去除）、金额异常标记 2,471 条（单独输出 `amount_outliers.csv`，不盲目删除以免误删批发大额订单）、无法对齐维度表的脏引用 0 条；清洗后事实表 33,123 行，净销售额 702,387.29 英镑，估算毛利 305,237.84 英镑。

导出格式：**CSV**（`data/clean/*.csv`）、**JSON**（`fact_orders_sample.json`）、**SQLite**（`data/clean/shop.db`，含 4 张表），便于复用与验证。
